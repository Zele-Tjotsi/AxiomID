# Security Policy

## Scope

AxiomID is an engineering project intended to demonstrate production-oriented identity and security engineering practices.

Security is treated as a first-class engineering concern throughout the project.

## Reporting a Vulnerability

Do not disclose security vulnerabilities through public GitHub issues.

For the purposes of this project, security findings should be documented privately until they can be assessed and remediated.

## Security Principles

AxiomID development follows these principles:

- least privilege
- defense in depth
- secure defaults
- explicit trust boundaries
- strong input validation
- protection of secrets
- auditable security-sensitive operations
- dependency management
- automated security testing
- documented threat models

## Security Documentation

Security architecture, threat models, reviews, and security decisions are maintained under:

`docs/security/`

and

`docs/threat-models/`

## Important Notice

AxiomID is an educational and engineering simulation.

It must not be used to protect production systems or real user credentials without a separate security review, threat assessment, testing program, and operational readiness process.
